# ZEISS IQS Service ChatBot

本项目是一个基于网页的智能客服聊天机器人。

---

## 关于网页版聊天与本地操作的区别

### 常见问题：网页里的 AI/Bot 能操作我本地电脑吗？

**简短回答：不能。**

网页端的聊天机器人（包括本项目）运行在服务器/浏览器环境中，**无法直接访问或操作你本地的文件、系统或程序**。

---

### 详细解释：信任边界（Trust Boundary）

#### 网页版聊天机器人（本项目 / ChatGPT 网页版 / 类似服务）

- 运行在**远程服务器**或**浏览器沙盒**中
- 只能接收你输入的文字/文件，在服务端处理后返回结果
- **没有权限读写你本地的文件系统**
- **没有权限执行你本地的命令或程序**
- **没有权限访问你本地的 VS Code、IDE、终端**
- 任何"工具调用"都发生在服务器端，不涉及你的本地环境

#### VS Code Copilot / 本地 IDE 插件（Agent 模式）

- **安装在你本地机器上的插件/扩展**，例如 GitHub Copilot 插件
- **由你主动安装并授权**，才能访问你的本地文件和工作区
- Agent 模式下可以：
  - 读取和修改你本地的代码文件
  - 跨文件执行多步任务
  - 在你授权范围内运行终端命令
  - 访问你当前打开的工作区/仓库
- 这些操作**全部需要你显式安装插件并授权**，不会绕过你的本地权限系统

---

### 对比总结

| 功能 | 网页版聊天 Bot | VS Code Copilot (本地插件) |
|---|---|---|
| 读取本地文件 | ❌ 不能 | ✅ 可以（需授权） |
| 修改本地代码 | ❌ 不能 | ✅ 可以（需授权） |
| 执行本地命令 | ❌ 不能 | ✅ 可以（需授权） |
| 访问本地 IDE | ❌ 不能 | ✅ 可以（在 IDE 内运行） |
| 回答问题/给建议 | ✅ 可以 | ✅ 可以 |
| 需要安装客户端 | ❌ 不需要 | ✅ 需要安装插件 |

---

### 为什么 VS Code Copilot Agent 模式"感觉能操作本地"？

因为 VS Code Copilot 是**安装在你本地 IDE 内的插件**：

1. **你主动安装**了 GitHub Copilot 扩展到 VS Code
2. **VS Code 本身**运行在你的本地机器上，有权访问你的文件系统
3. Copilot 插件通过 VS Code 的 API **借助 VS Code 的权限**来读写文件
4. 这整个过程**都发生在你的本地机器上**，AI 模型的推理在云端，但文件读写在本地

所以本质上：
- **AI 推理** → 在云端服务器
- **文件/代码操作** → 在你本地，通过你安装的插件

---

### 如何让 AI 能够操作你本地的文件？

只有以下几种方式，且**都需要你主动安装和授权**：

1. **安装 VS Code Copilot 插件**（GitHub Copilot 扩展）
   - 在 VS Code 的扩展市场搜索并安装
   - 登录 GitHub 账号授权

2. **安装其他本地 AI 工具**
   - 例如 Continue、Cursor、Codeium 等本地 IDE 集成工具
   - 均需要本地安装

3. **使用支持 MCP（Model Context Protocol）的工具**
   - 需要在本地配置和运行 MCP 服务器
   - 需要显式授权每个工具的权限

4. **使用带有文件上传功能的网页工具**
   - 你主动上传文件，AI 在服务端处理后返回结果
   - AI 本身仍然无法主动访问你的本地系统

---

### 安全提示

- **网页版 AI 聊天无法在未经你授权的情况下访问你的本地文件**
- **任何声称"网页版 AI 可以直接操作你本地文件"的说法都是错误的**
- 本地 AI 工具（如 VS Code 插件）在你授权后可以访问工作区，但仅限于你显式允许的范围
- 保护好你的 IDE 插件权限和 API 密钥

## 项目部署

本项目为静态网页应用，直接部署到 Web 服务器即可。

```
index.html        # 入口页面
umi.js            # 主应用打包文件
umi.css           # 主样式文件
p__Chat__*        # 聊天页面模块
p__Login__*       # 登录页面模块
p__SNInput__*     # 序列号输入页面模块
```
